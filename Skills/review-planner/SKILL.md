# review-planner

## What it does

Planner 的**回顧與對帳**引擎，三種節奏：
- **週回顧 + 下週準備**（週日）—— `/review-weekly` 指令的底層
- **月底對帳與總結**
- **年度盤點**（跨年整理）

與鄰居的分工：
- [`manage-planner`](../manage-planner/SKILL.md) — 每日交易操作（盤點/完成/新增）。本 skill 是週期性回顧。
- [`review-stage`](../review-stage/SKILL.md) — 策略反思（目標/效率/餘裕）。這裡的月/年總結**餵給** review-stage：回顧對帳檔案，review-stage 跨期詮釋。

資料模型（bullet 符號、格式、stream、migration）見 [`0_Planner/README.md`](../../0_Planner/README.md)。

## When to trigger

- 週日下班後，或「週回顧」/「做這週回顧」/「準備下週」/「本週做了什麼」
- 月底最後一天 / 下月第一天 → 月底
- 年底最後一週 / 新年第一週，或「做年度盤點」 → 年度

## 報告規則（適用全部三層回顧 — 唯一定義處）

以下每種回顧都遵守。只在這裡定義一次。

- **格式 = 清單/表格，絕不散文。** 不要把日期＋任務＋數字塞進段落。每段都是 bullet 或表格、一眼可掃。
- **精簡、零重複。** 每個 fact 只出現一次；交叉引用、不複製。
- **誠實命名沒達成的 Goal——不美化、不苛刻，診斷要對。** 兩種不同東西，別預設某一種：
  1. **失策（或跟預期不同）**——目標估錯/高估產能，是誤判，直說。
  2. **排序取捨**——刻意把產能讓給更高優先線，by design 順延、非 by error。別叫它失策、也別美化成「主動移轉」，就叫它排序選擇；必要時 flag 真正風險（複利延遲）。
  不確定 → 問使用者。
- **突發一律拆 `*` 殺入 vs `+` 衝刺。** 絕不報 lumped 總數：`*`（被插隊/被動）多＝過載；`+`（有空主動加碼）多＝有餘力。
- **各線盤點要量化 AND 詮釋。** 每 stream 給 完成數／殺入(`*`)數／延後(`[>]`)數，然後點出**一個**真正值得注意的訊號並解釋 WHY（raw counts 看不出的 read），別只枚舉。
- **中文標點全形。** `，、；：？！（）` 等，中文內（含表格/清單）絕不用半形。

## 週回顧 + 下週準備（週日）

### 週回顧
- 數完成項。
- **各 stream 量化**——給每條具體數字。**別寫「零進度」**（停滯但有累積寫「停在 X%、本週未推進」）。量化、別打發。
- **各 stream 一段敘述（必備）**——統計表之外，每條 stream 寫一段「這週實際在做什麼」。表格不夠。
- **設計/研究型工作的 % 不反映真實進展**——用文字描述實際做了什麼，別只靠數字。
- 亮點（按 stream）；突發拆 `*` vs `+`；延後項與去處。
- **習慣統計** → 交 [`track-habits`](../track-habits/SKILL.md)（飲料咖啡／茶分計、運動 做了幾次／目標…）。
- 仍在追的 pending 項。
- **兩軸抓漏**（對照時間軸與 `Collections/` 主題軸；連結約定＝`@collection` 標籤＋時間軸連結，見 Collections/README）：① 孤兒主題項（列很久、沒排進任何週）② 孤兒週任務（沒有 `@collection`、不屬任何主題）③ 停滯主題（連續數週零進度）。

### 下週準備
- **建立下週檔（必做、不問）**——從 [`recurring-items.md`](../../0_Planner/recurring-items.md) 預填例行會議＋習慣空格（如運動、相隔數天留恢復日），帶入本週遷移項與已確認行程，寫 `本週主題`。這是**例行操作、直接建**，不問「要不要建檔」；產物＝一份建好的下週檔。
- 拉入下週檔已有的 `[o]` 事件；找出延續項（前一週延過來、或已排定從某日開始的）；浮出衝突（會議重疊、假日撞期）。
- 呼叫 [`sync-calendar`](../sync-calendar/SKILL.md) 同步下週事件。

## 月底對帳與總結

**整檔對帳（必做）。** 逐 section 走過 Monthly 檔，標**每一行**：
1. **Goals** — 完成 `[x]`；結轉下月 `[>]`（附原因）；刻意放棄 `[ ]`。使用者說了算，別逼解釋。
2. **Calendar** — 過去 `[o]`：出席 `[x]`、取消/缺席 `~~刪除線~~`；未來留 `[o]`。
3. **例行** — 狀態不明就問使用者，別自動標。
4. **Tasks** — 完成 `[x]`、下月 `[>]`、明確降級才 `[ ]`。
5. **Completed** — 補上本月落地的策略級成果。
6. **Notes** — 留結構性筆記；加月底觀察。

**然後在檔尾寫 `## 月底總結`**：Goals 達成數／跨月項／突發 highlights／下月 focus。（遵守上方報告規則。）
更新 `> Last updated:`。狀態不明的例行（線下處理的繳費等）→ **明確問**、別假設。

## 年度盤點（跨年整理）

第二年起 Planner 不能無限堆疊。每年底/年初做一次，比月底高一層：

1. **歸檔舊年度**：`Weeks/2026_*.md` 與月檔 `2026-*.md` → 移入 `archive/2026/`（可查、不污染當前視圖）。
2. **結轉 goals**：`goals.md` 逐項——完成的標達成並隨歸檔留存；未完成的決定「結轉新年度／放棄／改寫」，寫入新年度 goals。
3. **回顧報告**：達成率、各 stream 投入分布、突發 `*`/`+` 全年佔比、tracker 趨勢 → 存 `archive/2026/year-review.md`。
   （深入的效率/餘裕跨期分析可交 [`review-stage`](../review-stage/SKILL.md)。）
4. **重設**：`recurring-items.md` 是否異動；tracker 起算日是否重訂。
5. **檔名年份隔離**：新年度自然從 `2027_MMDD-MMDD.md`、`2027-01.md` 起，不撞舊檔。

別讓一年無聲收尾——追蹤這件事真的有做。
