# review-stage

## What it does

**階段性**的自我盤點——不是每日/每週例行（那在 manage-planner / review-planner），而是**結構轉折點**
（季末、半年、換工作、專案退場…）的一次深度評估。回答像「上一段我做了什麼、下一段會不會比較輕鬆」
這種問題：讀 Planner 資料層，給出**有數據支撐**的判斷，寫成一份報告存到 `0_Planner/Reports/`。

三個步驟，依序：**目標 → 成果 → 過程 → 定論**。

## When to trigger

- 餘裕/效率問題：「下半年會不會比較輕鬆」「這階段忙不忙」「我是不是做很多事」
- 階段回顧：季末、半年、年中、換工作/專案結束等轉折
- 比較**兩個時期**的忙碌度或餘裕
- 想知道時間實際花到哪，跟自己以為的差在哪

不做每日/每週例行——那是 `manage-planner` / `review-planner`。

## 步驟一 — 目標盤點

讀 `goals.md` ＋ 月檔。每個目標：
- **狀態**：達成／進行中／順延／重排／放棄
- **為什麼**：分清 **失策（估錯／高估產能）** 與 **排序取捨（刻意讓路、是設計不是失誤）**——別混、也別美化
- 別把「手段」（賺錢／品牌／副業）當成「目標」；結案由使用者確認（未確認前標 `[~]`）

## 步驟二 — 成果盤點

這階段實際**產出**什麼。分清**深度成果**與**重複性雜務**（英文常叫 churn，如例行貼文、瑣事）：
- 里程碑（完成的具體事）
- 量的證據：跨週 `[x]` 累計 ＝「做很多」的實證（用 `scripts/busyness-scan.sh` 的完成量欄）
- 深度成果 vs 重複性雜務：重複性內容／瑣事 ≠ 里程碑推進；「動作很多但核心沒動」要點名
- 值得點名的訊號（反直覺、背離、跨期工程）

## 步驟三 — 過程分析（效率／餘裕／忙碌）— 5 招

看這段**怎麼過的**。先跑 `bash Skills/review-stage/scripts/busyness-scan.sh`（週檔從你開始用的那週起算，更早沒資料＝基線、別捏造）。

1. **忙碌曲線**——兩軸，別合併：**完成量**（`[x]` 數＝做多少）與 **突發占比**（`*` 突發 ÷ 完成量＝多混亂）。
   低量＋高突發% ≠ 輕鬆週（是被打斷，不是閒）。
2. **餘裕帳**——比兩期：列一張 **減載／加載的差異項表**，只放兩期間**會變的**項（兩期相同的排除，如都在同一份工作）。
   每項給**權重**（相對單位；難量化的**問使用者要數字**、別自己編）。**淨 = Σ減載 − Σ加載**，但別停在數字（見第 5）。
3. **負載三分類**（棘輪洞察）——依時間形狀分：**別人給的永久負載**（移除＝餘裕來源）/ **一次性專案**（有終點、會回落）/
   **自己加的永久負載＝棘輪**（永久墊高地板、無退路、早期常負 ROI）。分清**尖峰（會過去）vs 墊高地板（永久）**。
   棘輪型負載若在壓力期上線要示警——建議綁**條件**（時機成熟）不綁**日曆**、並用輕橋先鋪陳。
4. **突發產生器辨識**——單一來源可能同時是最大工作量**和**突發地板；移除它對餘裕的改善**大於**其工時。點名它。
5. **質 > 量 詮釋**——淨單位會低估/高估，用質重讀：餘裕 ≠ 沒事做，餘裕 = **事情在掌控裡**（可規劃、可預期）。
   忙從突發忙→計畫忙、或大目標卸下，即使總量幾乎不變也會明顯較鬆。

## 產出

寫到 `0_Planner/Reports/YYYY-MM-DD_<主題>.md`，骨架：

```
# <主題> — 階段回顧
> Date: YYYY-MM-DD · Method: review-stage

## 問題 / 觸發
## 方法與資料範圍     # 掃了哪些檔、資料限制（週檔起算週）
## 目標盤點           # 步驟一
## 成果盤點           # 步驟二（忙碌曲線完成量＝量的實證）
## 過程分析           # 步驟三（餘裕帳／負載三分類／突發產生器）
## 定論              # 用質，不只量
## 衍生決策           # 這次觸發的決定 + 記在哪
```

若某發現推翻了月/年檔裡寫過的假設，提出**整合式修訂**（把新發現疊上去、別默默覆蓋，浮出矛盾），使用者確認後才改。

## Rules

- **有數據、不憑感覺。** 每個忙碌/餘裕 claim 引用週/月計數或 grep 結果；週檔從你開始用那週起算，別捏造更早的週。
- **權重由使用者校準。** 難量化的負載問使用者要數字，別猜。
- **只有差異項進餘裕帳。** 兩期相同的排除。
- **別合併 量 和 質。** 兩軸都報，用質詮釋。
- **只進 Reports/。** 分析輸出進 `0_Planner/Reports/`，不新增其他 Planner 檔。
- **分析 ≠ 目標。** 絕不把盤點寫進 `goals.md`。
