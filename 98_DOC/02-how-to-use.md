# 使用教學 — 怎麼用 ai-pm-starter

這份教你**日常怎麼操作**：6 大指令的使用情境、用主題軸管長期專案、外來資料怎麼進系統、三個模組與三道安全閘是什麼。
（第一次設定請先跑 `/setup-aipm`，見 [README][def]。）

> 心法：你**不一定要打 `/指令`**——用自然語言講就好（「盤點一下」「記一筆」），AI 會確認情境後跑對的指令。slash 只是更快的捷徑。

## 介面小撇步（先學這幾個）

- **打 `/`**：在對話欄位輸入 `/` 會跳出**功能選單**，挑一個就跑、不用背名字。（選單列的是 Claude Code 內建 + 已載入的 skill。）
- **第一次 skill 還沒載入時**：剛 clone、剛開專案，`/setup-aipm` 這類斜線指令可能**還打不出來** → 別卡住，**直接用講的**：「請尋找並執行 setup-aipm 的步驟」，AI 會自己找到並做。（`↑` 叫回上一句、backspace 刪掉斜線。）
- **Shift + Tab**：切換 AI 的**運作模式**（一般「每次確認」↔「自動接受編輯」↔「計畫模式」）。想先規劃不動手、或想少被打斷時用它切。
- **嫌每次改檔都要按「允許」很煩**：權限跳出時可選 **「Allow all edits（這個 session）」**——這次工作階段內改檔就不再每次問（關掉重開會回到每次問，最安全）。想更系統地放寬見 [04-security](04-security.md) 或跑 `/safety-aipm`。

## 你的資料就是純文字 Markdown（.md）

這套系統裡所有東西——日誌、週檔、目標、會議記錄——都是 **Markdown（`.md`）純文字檔**。Markdown 就是用幾個簡單符號排版的純文字：`#` 是標題、`-` 列清單、`[ ]` / `[x]` 是待辦勾選框。

為什麼用它：

- **對 AI 最友善**：純文字、結構清楚，AI 讀寫都精準、不會卡在格式，改起來乾淨俐落。
- **你永遠打得開、不被綁死**：任何編輯器、任何裝置都讀得到，不依賴特定 App，多年後還在。
- **輕、可追蹤**：檔案很小，搭配 git 能記錄每次變更、回溯歷史（見模組 A）。

一句話：**乾淨的純文字，對 AI 友善、也對你友善。**

## 一張圖：東西怎麼進系統

```
你開口 ──► the-assistant（規劃）          ← 日常 90% 在這
外來檔 ──► the-gatekeeper 檢查 ─► (需加工?) the-smith ─► the-gatekeeper 放進倉庫
```

- **the-assistant**＝你的 Planner 助手（日常記錄、盤點、回顧）
- **the-gatekeeper**＝門＋倉庫（外來東西的檢查與歸位、三道安全閘）
- **the-smith**＝工坊（把外部 skill/雜亂文件加工成可用的道具/AI 好讀文件）

## 6 大指令 — 使用情境

### 1. `/log-work` — 記錄今日工作
**什麼時候用**：想記今天做了什麼、要做什麼，或回報完成/延後。
**怎麼說**：「記一筆：下午兩點開週會」「我寫完草稿了」「報稅延到明天」
**會發生什麼**：AI 找到今天的週檔，把事寫進對應 stream，用子彈符號（事件 `[o]`、待辦 `[ ]`、完成 `[x]`、延後 `[>]`）。
**範例對話**：
> 你：記一筆，今天事業線完成了直播，臨時又被叫去處理客訴
> AI：好，寫進 6/27 ✅ 事業：`[x] 直播`；生活：`[x] *處理客訴`（*=臨時殺入）。剩下：今天還有「繳房租」待辦。

### 2. `/check-now` — 盤點現況
**什麼時候用**：想知道現在有什麼沒做、有沒有漏掉的。
**怎麼說**：「盤點」「盤點今天」「還有什麼沒做」
**會發生什麼**：AI 先**確認情境**（今天的盤點？還是要做本週回顧？），然後列出未完成項；純「盤點」會回頭檢查過去幾天有沒有漏記（drift-check）。
**範例對話**：
> 你：盤點一下
> AI：你是要看今天的現況，還是做本週週回顧？
> 你：今天
> AI：今天還沒完成：工作 `[ ] 整理會議記錄`；生活 `[ ] 繳房租`。今天咖啡/茶喝了多少？

### 3. `/review-weekly` — 週回顧 + 下週準備
**什麼時候用**：週末/週日，想收一週、排下週。
**怎麼說**：「週回顧」「準備下週」
**會發生什麼**：AI 統計完成數、各 stream 進展（量化+敘述）、突發比例（`*` 殺入 vs `+` 衝刺）、延後項；再拉下週事件、寫下週主題。完成後提醒可順手同步行事曆。

> **更深一層——階段盤點**：週回顧收的是「這一週」；當你想知道「這半年／這一季會不會比較輕鬆」「我是不是做了很多事」時，用自然語言問一句就好，AI 會做 **階段盤點**（`review-stage`）：量化每週忙碌度、比較兩個時期的餘裕、產出一份報告存到 `0_Planner/Reports/`。這是季末／半年／轉折點才做的深度回顧，不是每週例行。

### 4. `/extract-todos` — 會議記錄抽待辦
**什麼時候用**：開完會、有一堆筆記/逐字稿，想變成可追蹤的待辦。
**怎麼說**：把筆記貼上 +「抽待辦」，或「這份會議我要做什麼」
**會發生什麼**：AI 先把筆記整理成結構化會議記錄（存 `0_Planner/meeting_logs/`），再抽出**你自己的** action items 放進 Planner。

### 5. `/ingest` — 匯入外部資料
**什麼時候用**：要把外面的檔案、PDF、甚至別人的 skill/agent 收進系統。
**怎麼說**：把東西丟進 `99_TEMP/`，再說「匯入這個檔」「把這份 PDF 收進來」「加入這個 skill」
**會發生什麼**：外來東西先進 `99_TEMP/` 暫存區，走**進件 pipeline**——the-gatekeeper 先在那裡**安全掃描**；需要加工（PDF/雜亂文件/外部 skill）就交 the-smith 整理成 AI 好讀或標準格式；分類放進對的 domain；最後問你要不要刪掉 `99_TEMP/` 的原始檔。
**範例對話**：
> 你：（把 PDF 放進 99_TEMP/）把這份專案規格收進來
> AI：① 掃描通過 ✅ ② 這是 PDF，交 the-smith 用 convert-pdf 轉成 Markdown ③ 放進 `2_Project/該專案/` ④ 要刪掉 `99_TEMP/` 的原始 PDF 嗎？

### 6. `/sync-calendar` — 行事曆同步（模組 B）
**什麼時候用**：想把月檔事件推到 Google Calendar，或把行事曆的事拉回來。
**怎麼說**：「同步行事曆」
**會發生什麼**：月檔 `## Calendar` 的 `[o]` 事件 ↔ Google Calendar 雙向同步（只有事件、不含任務）。預設 mock，設定見模組 B。

## 管長期專案：主題軸（Collections）

上面 6 個指令管的是**時間軸**（今天、這週要做什麼）。但**橫跨很多週的長期專案**（出書、改版網站、辦活動）光靠時間軸會散落各週、看不出全貌、容易爛尾——這時用 **Collections（主題軸）**：幫每個專案開一個檔，把它的所有任務聚在一處，再用 `@collection` 標籤跟週任務**雙向連結**。週回顧時 AI 會對照兩條軸，抓出「排很久沒動的項」「不屬任何專案的任務」「停滯的專案」。

**怎麼用、含範例，見 → [07-collections.md](07-collections.md)**（完整格式規格見 [`0_Planner/Collections/README.md`](../0_Planner/Collections/README.md)）。

## 三個模組

| 模組 | 是什麼 | 需要 |
|------|--------|------|
| **核心** | 規劃中樞 + AI 助手，純本機純 markdown | 只要 Claude Code |

## 三道安全閘（速查）

| 閘 | 擋什麼 | 你會遇到 |
|----|--------|---------|
| 內容閘（purge-file） | 外來檔案的威脅 | 匯入時 AI 說「掃描通過/發現問題」 |
| 指令閘（sandbox-guard） | 危險 Bash、逃出專案 | 危險指令被擋下、顯示 BLOCKED |
| 權限閘（deny/allow） | 危險動作擋、安全動作免問 | 跑 `/safety-aipm` 調整 |

逐次的權限確認是**正常的**（第一道防線）。覺得煩、想放寬，先讀 [04-security.md](04-security.md) 再跑 `/safety-aipm` 或看 [05-sandbox-guard.md](05-sandbox-guard.md)。

## 想讓 AI 更聰明？（進階，會更燒額度）

遇到難的、需要它想得更深的任務，可以切到**強化版**——AI 會變聰明、更會處理複雜問題，但**你的用量額度會更快用完**。兩個旋鈕：

- **換更高階的模型**：用 `/model` 切到更強的模型（例如 Opus 這類高階款）。處理難題更好，單次也更貴。
- **調高思考強度（effort）**：讓它「想久一點、想深一點」再回答。品質更好，但花更多 token。

**怎麼選**：規劃大方向、除錯、需要嚴謹推理時開強化版；日常「記一筆」「盤點」這種簡單操作用一般版就夠，省額度。額度快用完 → 用 `/model` 換回一般模型、把 effort 調低即可。

## 多開 session 平行做事（進階）

**一個 session ＝ 一輪對話，從開始聊到結束。** 想更有效率，可以**同時開好幾個 session、讓每個負責不同的事**——例如一個專心整理會議記錄、一個排下週計畫、一個處理剛匯入的檔案——這樣就能**平行處理多件事**，不必等一件做完才做下一件。

- **開新 session**：在 Claude Code 面板開「New session」。
- **一件事要跑很久時最划算**（例如在等安裝、等同步）→ 先切到另一個 session 做別的，不空等。
- ⚠️ **不同 session 一定要碰不同的檔、做不同的事**——**別讓兩個 session 同時改同一個檔案**，會互相打架、卡住。分開負責就沒事。

## 一天的典型節奏

1. 早上：`記一筆` 把今天要做的排進來
2. 隨時：完成就回報（`我做完X了`）、被插隊就記（`*臨時…`）
3. 傍晚：`盤點今天`，補記沒記到的、回答飲料/習慣 tracker
4. 週日：`週回顧`，收這週、排下週（順手 `同步行事曆`）
5. 年底：`做年度盤點`，歸檔、結轉目標、寫年度回顧
