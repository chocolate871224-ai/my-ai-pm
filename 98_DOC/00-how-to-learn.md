# 00 · 怎麼用這套教材學（先讀這篇）

**最重要的一句話：看不懂,就直接問 AI。** 你不需要先懂任何技術名詞——這套系統的重點就是「用講的」,AI 會用你的話跟你解釋、帶你做。

## 遇到狀況怎麼辦

| 你遇到 | 直接這樣跟 AI 說 |
|--------|------------------|
| **有個單詞/名詞看不懂**（commit、remote、token…） | 「`token` 是什麼?用白話講給我聽。」 |
| **某段說明看不清楚** | 「這段我看不懂,幫我換個方式解釋。」 |
| **某步操作做不出來 / 卡住** | 「我想做 X,但卡在 Y,接下來怎麼辦?」 |
| **某份教材整篇看不懂** | 用 `@` 把那份檔**指給 AI 讀**，再請它帶你做 → 「`@98_DOC/03-google-calendar-setup.md` 幫我照這份一步步帶我做。」 |
| **畫面跟教材對不上 / 真的看不懂** | **截圖丟給 AI**,並講清楚你想做什麼 → 「這是我的畫面（截圖）,我想做 X,幫我看現在該點哪裡。」 |

## 三個心法

1. **不用怕問「太基本」的問題。** 沒有蠢問題;AI 不會累、不會嫌煩。
2. **講清楚你「想做什麼」。** 比起「這是什麼意思」,「我想把今天的事記下來,該怎麼做」更好帶。
3. **真的卡住 → 截圖。** 文字描述不清楚時,一張螢幕截圖最快——丟給 AI、指明你要操作什麼,它會看著畫面告訴你下一步。

## 但也要盯著 AI——它會誤解、會自行腦補

AI 很強，但**不是永遠對**。它有時會「自行創造、偷渡概念、誤解你的意思」——最常見的是把**一次性的指示**悄悄擴大成**常規**。

真實例子：
> 你說：「這次 commit 完了**去** push。」
> AI 卻理解成：「**每次** commit 完都要**自動** push。」——把「這一次」偷偷變成「每一次」。

所以：
- **檢查它有沒有照你的意思做**，尤其當它「順便多做」或說「以後都這樣」的時候。
- 發現它理解錯 → **直接糾正**：「我是說『這次』，不是『每次』。」
- 它做的事你看不懂、或超出你要求的範圍 → **先喊停問清楚**，別放它自己跑。

## 想知道系統更新了什麼

這套系統會持續更新。想回頭看「改了什麼」，有兩個層級，都可以直接叫 AI 讀給你聽：

- **`CHANGELOG.md`（功能版本紀錄）**：每次對你有感的能力升級，用白話寫成一條一條。想快速了解「多了什麼功能」看這份。
- **`git log`（逐筆技術變更）**：每一個小改動的完整流水帳，比 CHANGELOG 細很多。想追某個檔到底怎麼變的看這裡。

不用自己會下指令——用講的就好：
> 「讀 `@CHANGELOG.md`，告訴我最近新增了什麼功能。」
> 「幫我看 git log，最近幾次改了什麼？用白話講。」
