# Planner

你的規劃中樞，由 **the-assistant** 操作。整合實體子彈筆記——你在紙本與數位之間手動同步。

> **本檔是 Planner 資料模型的唯一真實來源**——每個檔案/資料夾負責什麼、以及所有格式/慣例。
> `manage-planner` 引擎**操作**這些檔（怎麼操作，拆成幾條操作流程），不在那裡重複定義格式。

## 結構

```
0_Planner/
├── Weeks/              # 週誌 — 一週一檔（執行層）
├── meeting_logs/       # 會議記錄 — extract-todos 從這裡抽待辦
├── Collections/        # 主題軸任務清單（命名慣例＋設計原理見 Collections/README.md；Done/ 放完成）
├── archive/            # 年度歸檔 — 年度盤點時把舊年度檔案移進來
├── goals.md            # 年度目標 + Future Log
├── recurring-items.md  # 例行事項註冊表
├── Reports/            # 階段性自我盤點與評估（review-stage 產出；見 Reports/README.md）
├── 2026-06.md          # 月度（所有 stream 合併一檔）
└── README.md           # 本檔
```

**規劃層級由外而內**：`goals（年）→ 月 → 週`，未完成項隨時間往內/往後遷移（見 Migration）。
分析輸出（效率/餘裕盤點）另存 `Reports/`，不混進規劃檔。

## Work Streams（可自訂）

預設四條 stream。把它們改成你自己的人生領域即可——改完同步更新各檔案的 `### StreamName` 區段。

| Stream | 說明 |
|--------|------|
| 工作 | 正職、本業、受雇工作 |
| 生活 | 個人事務、家庭、健康、財務 |
| 事業 | 自己的事業、副業、品牌、創作 |
| 學習 | 進修、研究、課程、技能養成 |

> 自訂方法：決定你的 3–5 條領域，全面取代「工作/生活/事業/學習」。stream 是你看人生的切面，不是待辦分類。

## 時間層級

高層＝目標／事件，低層＝任務／動作。

| 層級 | 檔案 |
|------|------|
| 年 | `goals.md` |
| 月 | `2026-06.md`（`YYYY-MM.md`） |
| 主題 | `Collections/*.md` |
| 週 | `Weeks/2026_0622-0628.md`（`YYYY_MMDD-MMDD.md`，Mon–Sun 日期範圍） |

所有檔案用 `### StreamName` 區段區隔 stream。

**兩層：**
1. **策略層** — goals.md + Monthly
2. **執行層** — Weekly

## 用語對應（動作 × 情境 × 時間 → 交給哪個技能）

你講的一句話由三個維度組成，**「時間」決定用哪個技能（層級），「動作＋情境」決定做什麼**：

- **動作**：盤點／看＝列現況｜統計／對帳＝數與彙整｜分析／評估＝判讀。**統計和分析是同一件事，只是層級不同。**
- **情境**：工作／任務 ↔ 表現／效率／忙碌。
- **時間（決定層級）**：

| 你說的時間 | 交給 | 例句 |
|-----------|------|------|
| 今天／現在／還有什麼沒做 | `manage-planner`（`/check-now`）| 盤點今天、今天的工作 |
| 本週／這週 | `review-planner`（`/review-weekly`）| 盤點本週、這週的表現、週回顧 |
| 本月／月底・本年／年底 | `review-planner` | 統計這個月、月底對帳、年度盤點 |
| 這段時間／這陣子／這階段 | `review-stage` | 評估這段時間的效率、我是不是做很多事 |

**關鍵**：同一個「**盤點**」，接不同時間就是不同技能——**盤點今天 → `/check-now`；盤點本週 → `/review-weekly`**。

## Collections（主題軸）— 設計原理

Planner 有**兩條軸**，缺一不可：

- **時間軸**（goals → 月 → 週）：回答「**什麼時候做**」。
- **主題軸**（`Collections/`）：回答「**什麼屬於一起**」——一個專案/主題的完整面貌。

只有時間軸，長期主題會散落各週、看不出全貌、容易爛尾；只有主題軸，則不知何時動手。**兩軸並存、互相對照**，計畫才完整。同一份工作在兩軸各有一個家：時間軸上有「何時做」，主題軸上有「屬於哪個專案」。週回顧時對照兩軸，抓「列很久沒排的主題項」「不屬任何主題的週任務」「長期停滯的主題」。

**命名與狀態慣例（從檔名/位置一眼看出狀態）：**

| 狀態 | 標記 | 例 |
|------|------|-----|
| 持續性（永不結束）| `_` 前綴 | `_inbox.md`、`_reading-list.md` |
| 專案型（有終點・進行中）| 一般檔名 | `book-launch.md` |
| 完成 | `Collections/Done/` | `Done/website-revamp.md` |

- 正式 collection 必須有**明確主題名稱**；未成形構想先放 `_inbox.md`，成熟後升格。
- 結案移入 `Done/`。完整說明見 [`Collections/README.md`](Collections/README.md)。

## 週誌慣例

一週一檔，七天都在裡面。週日是總結日，含週回顧 + 下週準備。

- **檔名**：`YYYY_MMDD-MMDD.md`，週一到週日的日期範圍（例：`2026_0622-0628.md` = 2026/6/22 一 ～ 6/28 日；年份用 Monday 的年）
- **每日區段**：四條 stream + Notes
- **週日加**：週回顧、下週準備
- **飲料追蹤（範例 tracker）**：在星期標題後標 `｜CT`，例 `## 6/23（二）｜CT`。C=咖啡、T=茶。這是「自訂每日追蹤」的示範，換成你想追的習慣即可（記得先設起算日，見下）。
- **突發事項前綴**：
  - `*` **臨時殺入**（被動接招：別人丟來、臨時要救的事）
  - `+` **臨時衝刺**（主動加碼：自己決定額外多做的事）
  - 例：`- [x] *處理客訴`、`- [ ] +多寫一章草稿`

**範例：**
```markdown
# Week 2026_0622-0628（6/22 一 - 6/28 日）

> 本週主題：xxx
> Last updated: yyyy-mm-dd

## 6/23（二）｜CT
### 工作
- [ ] 準備週會簡報
### 生活
- [ ] 繳房租
### 事業
- [o] 19:00 直播
### 學習
_(none)_
### Notes
- 想法：...

## 6/28（日）
### 工作
- [ ] *臨時被指派的報告
...
### 週回顧
- ...
### 下週準備
- ...
```

## 自訂每日追蹤（tracker）的起算日通則

要開始追任何習慣／指標（飲料、運動、早起…）時，**先設一個起算日**，之後只從那天起算、不回溯補算。
例：「2026-06-23 起記錄飲料」。換掉飲料範例、加新 tracker 時都套這條。

## Bullet 符號

| 符號 | 意思 |
|------|------|
| `- [ ]` | 任務 |
| `- [x]` | 完成（真的做完了）|
| `- [>]` | 順延（migrate 到後續，一定註明去處 `延 M/D`）|
| `- [<]` | 排程到 future log |
| `- [o]` | 事件／會議 |
| `- [~]` | **部分完成**（註明 % 或剩什麼）|
| `~~文字~~` | **取消／沒發生**（跳過的事件用這個，**絕不用 `[x]`**）|

- **`*` 前綴** = 臨時殺入（被外力插隊/打斷的突發，被動、消耗）
- **`+` 前綴** = 臨時衝刺（突然有空主動加碼的突發，主動、有餘力）
- 兩者都正當、都不算「偏離計畫」；其**解讀**（殺入多=過載 / 衝刺多=有餘力）在週回顧做（review-planner）。

**刪除 vs 劃掉（語意不同，別混）**：
- **刪除** = 整行移除、**不留痕跡**。用在這項根本不該在清單上、要它消失無蹤。
- **劃掉** = 移出 active 清單但**保留紀錄**（`~~刪除線~~` ＋ 一句原因，如 停開/取消/本週不做）。不確定使用者要哪個，問一次。

## 任務格式

父任務＝簡單動詞 + 主題；縮排項目＝該任務的具體 checklist 步驟。

```markdown
- [ ] 整理行銷資料 @priority:P1 @energy:low
  - [ ] 聽完 A podcast
  - [ ] 做成框架筆記
  - [x] 初步研究
```

**規則：**
- tag 只標在父任務。
- 父任務名稱要清楚、可執行，別含糊。
- checklist 要具體（有名稱／連結就附上）。
- 完成或不再相關的就刪，別留垃圾。

## 任務 Tag

行末 `@tag:value`，全部可選，有預設值。

| Tag | 值 | 預設 |
|-----|----|----|
| `@energy` | `high` / `mid` / `low` | `mid` |
| `@cost` | `high` / `mid` / `low` | `low` |
| `@priority` | `P1`（必做）/ `P2`（該做）/ `P3`（可做） | `P2` |
| `@result` | 自由文字 | 空 |
| `@stream` | stream 名 | 由區段推斷 |
| `@date` | `YYYY-MM-DD` | — |
| `@gcal` | Google Calendar 事件 id（只在月檔） | — |
| `@collection` | collection 的主題名（把這個週任務連到某個主題）| — |

## Weekly vs Monthly 分工

| 層級 | 內容 | 何時填 |
|------|------|--------|
| **Weekly** | 當天具體工作、執行細節、會議、雜事 | 每天更新 |
| **Monthly** | 當月大方向目標 + 有日期的會議/事件 + 這個月要完成但未定日期的事 | 月初建立，過程中補 |

**Weekly 不回灌 Monthly** — Weekly 是執行層、Monthly 是目標層；只有長期未來工作才納入 Monthly。

**Monthly 檔格式**——sections：`## Goals / ## Calendar / ## 例行 / ## Tasks / ## Completed / ## Notes`
- **Goals**：當月大方向（約 3 個、彈性）；扁平編號清單、每條標 stream（`1. [ ] 完成草稿（事業）`）；
  **位置＝優先序（不用 `@priority` tag）**。目標受現實影響、延期/結轉/改範圍都正常，別當「例外」逼解釋。
- **Calendar**：帶日期的事件/會議。**帶時間者記 `[o]` 並同步 GCal**；`@gcal:<id>` **只在此 section**（Weekly 唯讀鏡像）。
- **例行**：來自 `recurring-items.md` 的可預期義務（繳費等）。
- **Tasks**：持續性 case work。一次性零星雜事放週檔、不放 Monthly。

## 例行事項

例行事項的單一真實來源是 [`recurring-items.md`](recurring-items.md)。
生活狀況改變（換工作、新習慣、新責任）時直接編這個檔；建立新 Weekly / Monthly 時從這裡預填，並標出假日／固定事件衝突。

## 會議 Know-How — 一串連續動作

排入一場會議時，把它當成一條動作流，自動檢查：

1. **排入會議**（Monthly/Weekly 標 `[o]`）
2. **會議前** → 需要紙本嗎？（議程、資料）→ 前一天排「列印」任務；審查型會議 → 前一天排「準備簽到表」
3. **會議當天** → 在當天 section 記重點
4. **會議後 1–2 天** → 排「整理會議記錄」→ 正式記錄存入 `meeting_logs/`（之後可用 extract-todos 抽待辦）

## Migration

- **Weekly → 下週**：週日檢視未完成，migrate 到下週（原項標 `[>]`）。
- **Monthly**：月底檢視——仍相關→複製到下月（原標 `[>]`）；現在不做→future log（標 `[<]`）；完成→`[x]`。

## 年度盤點（跨年整理）

第二年開始，Planner 不能無限堆疊。每年底／年初做一次盤點：

1. **歸檔舊年度**：`Weeks/2026_*.md` 與月檔 `2026-*.md` → 移入 `archive/2026/`（可查、不污染當前視圖）。
2. **結轉 goals**：`goals.md` 逐項檢視——完成的標達成並隨歸檔留存；未完成的決定「結轉新年度 / 放棄 / 改寫」，寫入新年度 goals。
3. **回顧報告**：達成率、各 stream 投入分布、突發 `*`/`+` 佔比、tracker 趨勢 → 存 `archive/2026/year-review.md`。
4. **重設**：recurring-items 是否異動；tracker 起算日是否重訂。
5. **檔名年份隔離**：週/月檔一律帶年份前綴，跨年自然不撞檔；新年度第一週從 `2027_MMDD-MMDD.md` 起。

> 叫 the-assistant「做年度盤點」即可觸發；沒裝 skill 也能照上面手動做。
