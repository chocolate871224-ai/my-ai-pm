# Collections — 主題軸任務清單

> Planner 的**主題軸**。一個 collection = 一個主題／專案的完整面貌——把散落各週的相關工作聚成一處看。

## 為什麼要兩條軸（設計原理）

你的計畫有兩種看法，缺一不可：

- **時間軸**（`goals.md` → 月檔 → `Weeks/`）：回答「**什麼時候做**」——今天、這週、這月的執行。
- **主題軸**（`Collections/`）：回答「**什麼屬於一起**」——某個專案/主題的全貌、進度、還缺什麼。

只有時間軸，長期主題會散落在各週、看不出全貌、容易半途爛尾；只有主題軸，則不知道何時動手。**兩軸並存、互相對照**，計畫才完整——這就是 collections 存在的理由。同一份工作，在時間軸上有「什麼時候做」的家，在主題軸上有「屬於哪個專案」的家。

## 命名與狀態慣例（從檔名／位置一眼看出狀態）

| 狀態 | 標記 | 範例 |
|------|------|------|
| **持續性**（永不結束、持續累積）| `_` 前綴 | `_inbox.md`、`_reading-list.md` |
| **專案型**（有終點、進行中）| 一般檔名 | `book-launch.md` |
| **完成** | `Done/` 資料夾 | `Done/website-revamp.md` |

## 命名紀律

- 正式 collection **必須有明確主題名稱**——模糊的分類名（如「雜項」「一些想法」）不合格。
- 未成形的構想先丟 **`_inbox.md`**（持續性暫存區）；概念成熟後才**升格**為具名 collection、並從 inbox 移除。
- 主題結案後移入 **`Done/`** 歸檔，主資料夾只留進行中／持續性的。

## 與時間軸的對照（週回顧時做）

collection 裡的項目，要做時就排進當週／當月（時間軸）。兩條軸用**輕量標籤、手動**互相連結（不做複雜的編號系統）：

- **週任務 → 主題**：在週檔的任務行加 `@collection:<主題名>`，例：`- [ ] 開發付款串接 @collection:book-launch`。
- **主題項 → 時間**：在 collection 裡的項目後面加一個「時間軸連結」，標出排進了哪一週，例：`- [ ] 開發付款串接 → 排 2026_0720`；還沒排進任何一週的就留空。

週回顧時對照兩軸，抓三種漏：

- **孤兒 collection 項**：列很久、卻沒排進任何週／月（沒有時間軸連結）→ 該排就排、該砍就砍。
- **孤兒週任務**：不對應任何目標／主題（沒有 `@collection`）→ 歸類到某個主題，或標示出來。
- **停滯主題**：某個 collection 連續數週零進度 → 推進它、或封存它。

## 檔案格式

檔首：`# 標題` ＋ `> Stream:` ＋（視需要）`> Source:` / `> 狀態:`，其後為任務清單（`- [ ]` / `- [x]`）。

每個項目可在行末加**時間軸連結**（`→ 排 2026_0720`），標出它排進了哪一週；還沒排的就留空——週回顧時，這種「列很久卻沒排」的項就是要處理的孤兒。
